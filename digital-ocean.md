# DigitalOcean VPS Migration & Streaming Optimization Guide

This guide documents the changes, engineering approaches, and deployment steps used to migrate the **Daisy Discord Music Bot** from a local Raspberry Pi to a 24/7 DigitalOcean VPS.

---

## 1. Background & Objectives

* **High-Quality Audio:** Eliminate stream stuttering, glitching, and sudden track skips.
* **Datacenter Bypass:** Resolve YouTube's aggressive bot check blocks (`Sign in to confirm you're not a bot`) that target cloud hosting IP ranges.
* **24/7 Uptime:** Host the bot in a secure datacenter with high bandwidth, independent of home network reliability.

---

## 2. Code-Level Optimizations (Mac ➔ VPS)

We modified **three files** in the codebase to make streaming resilient to network drops and bypass speed throttling.

### A. HTTP Headers Injection & Reconnection Shield (`music/player.py`)
To prevent YouTube from throttling the audio stream download speed, we capture the exact browser credentials (HTTP headers) generated by `yt-dlp` and pass them to FFmpeg. We also added `-reconnect_at_eof 1` to ensure FFmpeg automatically reconnects during a brief connection drop instead of skipping the song.

```python
# Modified segment in player.py (_run method)
resolved = await item.source() if callable(item.source) else item.source
if isinstance(resolved, dict):
    source_value = resolved["url"]
    headers = resolved.get("headers", {})
else:
    source_value = str(resolved)
    headers = {}

if item.duration is None:
    item.duration = await asyncio.to_thread(probe_duration, source_value, self.ffmpeg)
    # ...

# 1. Add reconnect_at_eof and reconnect_streamed flags
before_opts = "-nostdin -reconnect 1 -reconnect_streamed 1 -reconnect_at_eof 1 -reconnect_delay_max 5"

# 2. Safely parse and inject HTTP headers
if headers:
    header_str = "".join(f"{k}: {v}\r\n" for k, v in headers.items())
    import shlex
    before_opts = f'-headers {shlex.quote(header_str)} ' + before_opts

source = discord.FFmpegOpusAudio(
    source_value,
    executable=self.ffmpeg,
    before_options=before_opts,
    options="-vn",
)
```

### B. Extracting Headers & Cookie Support (`music/youtube.py`)
We modified `YouTubeClient.stream_url` to:
1. Check if a `cookies.txt` file exists in the project root. If present, it loads it into `yt-dlp` to verify the session.
2. Return both the stream `url` and the matching `http_headers`.

```python
# Modified segment in youtube.py
@classmethod
def _stream_url(cls, video_url: str) -> dict[str, str | dict]:
    if not is_youtube_url(video_url):
        raise YouTubeError("Only YouTube URLs are accepted")
    
    opts = cls.STREAM_OPTIONS.copy()
    # Load cookies file if present to bypass bot-checks
    if os.path.exists("cookies.txt"):
        opts["cookiefile"] = "cookies.txt"
        
    try:
        with yt_dlp.YoutubeDL(opts) as ydl:
            info = ydl.extract_info(video_url, download=False)
    except Exception as exc:
        raise YouTubeError(str(exc)) from exc
        
    stream = info.get("url") if info else None
    if not stream:
        raise YouTubeError("YouTube returned no playable audio stream")
        
    return {
        "url": stream,
        "headers": info.get("http_headers", {})
    }
```

### C. Resolver Types (`bot.py`)
We updated the inner `resolve()` callback type annotation in the `/youtube` slash command to support the new dictionary returns:
```python
async def resolve() -> dict[str, str | dict]:
    return await YouTubeClient.stream_url(result.url)
```

## 3. The VPS Bot-Bypass Architecture

Hosting on a datacenter IP (DigitalOcean) triggers YouTube's bot-detection mechanism. We resolved this using a **Double-Lock Bypass**:

1. **Lock 1 (Bot Block) ➔ Bypassed by the "Static" Incognito Cookie Method**: 
   Since Google blocks concurrent session sharing (e.g., active browsing on your Mac while the VPS is streaming), we must use a frozen/static session:
   * **Incognito Window:** Open a private/incognito browser window on your Mac.
   * **Burner Account:** Log into a secondary (burner) Google account on YouTube (protects your main personal account from flags).
   * **Export:** Use the browser extension (like "Get cookies.txt LOCALLY") to export cookies in **Netscape format**.
   * **Immediate Close:** Close the private tab/window immediately without playing videos. This ensures the session key is only used by the VPS in Singapore, which keeps it valid for **3 to 6 months**.
   * **Upload:** Copy the cookies to the project root directory on the VPS as `cookies.txt`.
2. **Lock 2 (Encryption/n-signature puzzle) ➔ Bypassed by Deno**: YouTube requires executing player JavaScript to resolve stream decryptions. Because standard VPS servers do not have a JavaScript runtime, we installed **Deno** (the modern JS engine) and added it to `/usr/bin/deno`. `yt-dlp` uses Deno to solve these puzzles.

## 4. Manual Deployment Guide (No-Git Workflow)

If you are deploying local testing files from your Mac to the Droplet without committing to Git:

### Step 1: Zip & Transfer Files (On Mac Terminal)
```bash
# Navigate to project
cd /Users/tklwin/GithubRepos/burmese-discord-music-bot

# Compress files (excluding venv/git/caches)
zip -r project.zip . -x ".venv/*" -x ".git/*" -x "__pycache__/*" -x "*.DS_Store"

# Transfer files and cookies to Droplet
scp project.zip root@YOUR_DROPLET_IP:/root/
scp cookies.txt root@YOUR_DROPLET_IP:/root/burmese-discord-music-bot/
```

### Step 2: System Setup (On Droplet Terminal)
```bash
# SSH into Droplet
ssh root@YOUR_DROPLET_IP

# 1. Install System dependencies
apt update && apt install python3-venv python3-pip ffmpeg libopus-dev build-essential unzip -y

# 2. Install Deno (JavaScript Runtime)
curl -fsSL https://deno.land/install.sh | sh
cp /root/.deno/bin/deno /usr/bin/

# 3. Extract the project code
mkdir -p /root/burmese-discord-music-bot
mv /root/project.zip /root/burmese-discord-music-bot/
cd /root/burmese-discord-music-bot
unzip project.zip

# 4. Configure Virtual Environment & requirements
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
pip install -U yt-dlp-ejs  # Solver package
```

### Step 3: Run the systemd 24/7 service (On Droplet Terminal)
Create the service configuration:
```bash
nano /etc/systemd/system/discord-music-bot.service
```

Paste the configuration:
```ini
[Unit]
Description=Daisy Discord Music Bot (Cloud)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/burmese-discord-music-bot
ExecStart=/root/burmese-discord-music-bot/.venv/bin/python bot.py
Restart=on-failure
RestartSec=5
Nice=-10

[Install]
WantedBy=multi-user.target
```
*Reload, start, and set the service to run on boot:*
```bash
systemctl daemon-reload
systemctl start discord-music-bot
systemctl enable discord-music-bot
```

## 5. Server Management Commands

Use these commands on your Droplet to manage the bot:

| Command | Action |
| --- | --- |
| `systemctl status discord-music-bot` | Check if the bot service is active, stopped, or has crashed. |
| `journalctl -u discord-music-bot -f -n 50` | Stream real-time console output and errors (Follow mode). |
| `systemctl restart discord-music-bot` | Restart the bot (required after updating `.env` or uploading a fresh `cookies.txt`). |
| `systemctl stop discord-music-bot` | Stop the background service. |
| `systemctl start discord-music-bot` | Start the background service. |

### How to Update yt-dlp (Run if videos fail to play in the future)
If YouTube updates its signatures and tracks start failing, run these commands inside the Droplet terminal to update `yt-dlp` and its EJS plugin:
```bash
cd /root/burmese-discord-music-bot
source .venv/bin/activate
pip install --upgrade yt-dlp yt-dlp-ejs
systemctl restart discord-music-bot
```
